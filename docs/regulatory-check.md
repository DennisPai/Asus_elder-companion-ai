## §2. PDPA 2025/12 修訂版（2025/11 立法院三讀通過） 詳細對映

### §2.1 個資範圍分類（本案適用）

| 資料類型 | PDPA 分類 | 本案設計 | Priority |
|---|---|---|---|
| **對話文字摘要**（去敏感化後）| 一般個資 | 雲端儲存（PostgreSQL / GCP asia-east1）；保留 90 天，用戶可隨時申請刪除；consent_version 欄位追蹤同意版本 | high |
| **原始語音串流**（麥克風音訊）| 特種個資（§6 生物特徵相鄰）| **端側不出境**；wake word 100% 端側；音訊 7 天硬刪；**絕不雲端永久儲存** | **critical** |
| **健康相關對話**（長者健康問答語句）| **特種個資（§6 健康、醫療）** | Layer 2 rule-based 觸發後不路由 LLM；只記錄「觸發事件類型 + timestamp」，不記錄原始語句內容 | **critical** |
| **緊急偵測訊號**（跌倒 / 異常行為 flag）| 一般個資（非生物特徵本身）| 僅傳 event_type + confidence 結果（不傳音訊或影像本身）；保留於 emergency_event 表 | high |
| **環境影像**（攝影機）| **特種個資（§6 生物特徵）** | **完全不收集至雲端**（N9 絕對紅線）；攝影機僅限長者主動發起視訊通話 | **critical（blocker）** |
| **子女摘要 metadata**（推播內容）| 一般個資 | 保留 180 天；子女 App 可刪除 | medium |
| **緊急聯絡人清單**（姓名 + 電話）| 一般個資 | 僅用於緊急通知；不分享第三方；端側快取 | high |

**PDPA §6 特種個資雙重要求**：✅ desk-validated
1. 需有「明示同意書」（非僅勾選框），格式規定：以書面或可辨識之方式取得
2. 健康資料不得用於廣告目的、行銷、商業推薦（N10 紅線強化）

### §2.2 三方同意機制設計（W5-6 必完成）

> **設計依據**：safety-redlines.md §6.1 + tech-architecture.md §4.4 + PDPA §7-8 三方交叉驗證

**Step 1：子女書面同意（線上 onboarding，20-30 分鐘）** 📋
```
必完成項目：
- 閱讀 ToS 音訊版 + 大字版（可近性設計）
- 了解 AI 能力邊界白話說明（10 條絕對紅線 + 5 條條件紅線）
- 確認隱私設定（監控功能預設關閉）
- 電子簽名 + 同意版本記錄（consent_version 入 DB）
- 三方同意中的「書面同意方」
```

**Step 2：長者語音同意（由機器人執行，台語 + 國語）** 📋
```
語音說明腳本（標準版）：
「我是 [產品名]，我可以陪您聊天、幫您提醒事情，
 但我不是醫生，有病一定要看醫生。
 您的兒女可以知道我們聊了什麼的大概，但不是每句話。
 如果您不想用，隨時告訴我或告訴兒女都可以。
 您同意嗎？」

長者語音確認記錄：
- 「好」「知道了」「可以」均記錄為有效口頭同意
- 錄音摘要（非原音）存入 consent_log 表
- 若長者明確拒絕 → 提示子女暫停服務（尊重長者自主）
```

**Step 3：第三方見證（高風險情境）** 📋
```
觸發條件：
- CMS 3+ 級以上（中度照護需求）
- MCI 確診長者
- 長者獨居 + 認知能力有疑慮

見證人選項：
- 機構照服員（Hypothesis B 場景）
- 社區關懷員
- 醫療社工師
- 律師 / 公證人（最高保障）

見證記錄：
- 見證人姓名 + 職稱 + 見證日期
- 文字確認：「長者在清醒 / 理解狀況下表示同意」
- 存入帳號 consent_witness 表
```

**MCI / 認知退化後的持續同意機制** 📋
```
每 6 個月 re-consent 確認（若 MCI 進程可能加速）
子女可啟動「代理模式」（全權管理設定）
但不可關閉長者的「拒絕接受對話」基本功能
```

### §2.3 跨境傳輸合規路徑

**問題核心**：OpenAI API（美國）+ Azure TTS（東亞）+ Google STT（美國）均屬 PDPA §21 境外傳輸觸發範圍 ✅

| 傳輸路徑 | 資料內容 | 風險等級 | 合規策略 |
|---|---|---|---|
| 端側 → GCP asia-east1（台灣彰化）| 音訊 chunk（Opus 編碼）| **medium**（台灣節點大幅降低風險）| 主要部署節點；不屬嚴格「境外」|
| GCP asia-east1 → OpenAI API（美國）| 對話文字摘要（已去敏感化）| **high（PDPA §21 觸發）** | 三方同意書明示「您的對話摘要將透過 OpenAI API 生成回應」；嚴格資料最小化（無姓名/身分證/精確地址） |
| GCP asia-east1 → Azure TTS（East Asia）| SSML 文字（AI 生成語句）| **low**（不含長者原始資料）| TTS 為 outbound 文字轉音訊，不含長者隱私 |
| 端側 → Google STT V2（asia-east1）| 音訊 chunk（16kHz）| **medium**（台灣節點）| 音訊 7 天硬刪；同意書明示 STT 服務 |
| 任何節點 → 中國大陸 | **完全禁止** | **critical（blocker）** | 架構絕不對接中國節點；Azure/GCP 備援不走中轉路徑 🟡 待律師確認 HK 節點定性 |

**保守策略（PDPC 解釋令不確定期間）** 🟡：
- 對話摘要做嚴格資料最小化：無長者姓名、無 PII、僅含主題 + 情緒標籤
- Year 1 提高開源 LLM 比例（Llama-3 / Qwen），降低 OpenAI API 跨境依賴
- GCP asia-east1 台灣節點為主要部署（tech-architecture.md §1.2 確認）

### §2.4 資料保留 + 刪除機制

| 資料類型 | 保留期間 | 刪除機制 | 法規依據 |
|---|---|---|---|
| 對話文字摘要 | 90 天（預設）| 每日 03:00 cron 自動刪除 `retention_until < CURRENT_DATE` | PDPA §11（停止處理義務） |

## §3. AI 基本法 2025/12 影響

> **施行時間**：2026/1/14 已施行 ✅
> **子法規**：各目的事業主管機關於施行後 2 年內（2028/1 前）配套修訂 🟡

### §3.1 透明性義務（本案直接適用）

**要求**：用戶須知 AI 在對話（AI 基本法第 7 條透明原則）✅

本案設計回應：
| 義務 | 本案設計 | 實作時點 |
|---|---|---|
| 告知用戶是 AI | 每次對話開始語音提示「我是您的陪伴助手 [產品名]…」| Sprint 1 Week 1 |
| 不擬人化至誤導程度 | 不宣稱「我有感情」「我是真實朋友」；R9 紅線（safety-redlines.md §4.2）| Sprint 1 system prompt |
| 決策過程可理解 | ToS 明載 AI 能力邊界 + 7 條絕對不做的事 | W4 律師 ToS 完成 |
| 不替代人類最終決策 | 緊急偵測後「建議撥 119」不自行判斷；所有醫療 / 法律 / 財務問題均 handoff | Layer 2 守門器 Sprint 1 |

### §3.2 可究責性（幻覺 / 誤判的責任歸屬框架）

🟡 以下為規劃書等級，需 W6 律師 sign-off

| 場景 | 責任方 | 法律基礎 | 防禦設計 |
|---|---|---|---|
| AI 一般話題輸出錯誤（天氣 / 歷史）| 公司（修正義務）| 消保法 §7 | ToS 載明「AI 可能出錯，重要事務請確認」|
| AI 觸及醫療紅線但 Layer 2 未阻斷 | **公司（消保法 §7-1 舉證倒置）** | 消保法 §7-1 | Layer 2 雙層守門（端側 + 雲端）；事後 redline_triggers 表稽核 |
| AI 自殺危機訊號未偵測造成傷害 | **公司 S0 最高嚴重度** | 心理師法 §42 + 刑法過失相關 | Layer 2 關鍵字清單 + 後台人工確認（WoZ 階段）|
| 緊急偵測 False Negative（真跌倒未偵測）| 公司（中高，需 ToS 明載）| 消保法 §7 | ToS 明載「非醫療安全設備，建議保留傳統緊急按鈕」|
| LLM 台語辨識錯誤導致誤解（非緊急）| 公司（Fairness Audit 義務）| AI 基本法公平原則 | Fairness Audit（台語 / 客語 / 外省 ≥10 句，差距 ≤15pp）|

### §3.3 高風險 AI 系統定義（待子法規）

**本案可能觸發高風險分類的功能** 🟡：
- 緊急偵測（跌倒 / 異常行為）→ 涉及生命安全判斷
- 認知狀態監測（MCI 跡象偵測）→ 涉及脆弱族群健康評估
- 情緒危機偵測（自殺意念關鍵字）→ 涉及心理健康安全網

**合規策略（子法規公布前的預防性設計）**：
1. 申請 NSTC AI 監理沙盒（AI 基本法 §19 條款）📋

3. 保持 privacy by design + 透明性宣告作為預防性合規基礎 ✅
4. 每季追蹤 NSTC 子法規公告進度 📋

## §4. 消保法 + 公平交易法

### §4.1 廣告合規紅線

**消保法 §22 + 公平交易法 §21 合規要求** ✅

| 禁用宣稱類型 | 具體例子 | 替代表述 |
|---|---|---|
| 治療功能宣稱 | 「使用後改善失智症狀」「治療孤獨感」| 「陪伴互動，豐富長者日常生活」|
| 診斷功能宣稱 | 「精確偵測跌倒」「判斷認知退化程度」| 「異常感測後通知家人確認」|

| 取代真人照護 | 「有我就不用 24 小時陪護」| 「輔助子女遠距關懷，補充（非取代）真人陪伴」|

### §4.2 定型化契約合規設計

**消保法 §11 + §19 + 行政院消保會指引** 📋

ToS 必備條款（W4 律師起草，W6 律師審查）：

| 條款類型 | 要求 | 消保法依據 |
|---|---|---|
| 服務邊界聲明 | 「本服務為陪伴輔助工具，不具醫療、法律、財務顧問功能」| §11 不公平條款禁止 |
| AI 免責聲明 | 「AI 對話內容可能出錯，重要事務請諮詢專業人員」| §7 安全責任 + §11 |
| 服務停止預告 | 提前 **90 天**書面通知（消保法 §19 最低要求）+ 按比例退費 | §19 |
| 七日鑑賞期 | 訂閱制首月 7 日內無條件取消（數位服務適用性需律師確認 🟡）| §19 |
| 退費機制 | 月費剩餘天數按比例退費；硬體押金（若有）退還 | §19 |
| 個資同意授權 | 明確 PDPA 三方同意 + 跨境傳輸同意 + 可撤回聲明 | PDPA §7 + 消保法 §11 |
| 緊急服務免責 | 「本服務緊急偵測為輔助通知，不保證緊急救援到達時間或救援結果」| §7-1 + 消保法 |
| 長者保護條款 | 「本服務承諾不對長者端進行任何商品推銷、訂閱升級誘導」| N10 紅線對映 |

### §4.3 七日鑑賞期的數位服務適用性 🟡

現行消保法 §19 對「已提供之數位內容或一次性服務」有例外規定（通訊交易解除權合理例外情事適用準則）。

訂閱制 SaaS 的七日鑑賞期適用方式需律師 W4 確認：
- **方案 A（保守）**：首月 7 日內無條件取消 + 全額退費
- **方案 B（一般）**：首月 7 日試用期，使用後折舊退費
- 本案建議：**方案 A 保守**，配合 Vulnerable Population 保護原則

## §5. 醫療法 + 藥事法邊界

### §6.1 老人福利法關鍵條文對映

| 法條 | 條文要旨 | 本案設計對映 |
|---|---|---|
| **§10** | 老人知情同意與自主決策 | 三方同意機制確保長者本人理解並確認（語音同意 + 大字說明）|

### §6.2 詐騙防範設計（老人福利法 §43 + 公平交易法 §25）

**高風險場景識別** ✅：
1. 推銷商品 / 保健品 → N10 絕對紅線（對長者端零推銷）
2. 假冒子女 / 醫師口吻 → system prompt 禁止 AI 宣稱代表任何真實身份
3. 緊急假冒詐騙（「你家人出事了，需要匯錢」）→ AI 遇到此場景立刻警告 + handoff
4. 宗教付費誘導 → N7 紅線（宗教中立，禁止任何宗教捐款建議）

**反詐騙警告語庫**（Layer 2 觸發）：
- 「有人請您轉帳或匯款？這可能是詐騙，請先掛斷電話，再打電話給您的兒女確認。」
- 「165 反詐騙專線可以幫您確認這是不是詐騙，要不要我告訴您電話號碼？」

### §6.3 三方同意機制 vs 信託 / 監護人特殊情境

| 情境 | 法律框架 | 本案設計 |
|---|---|---|
| 一般長者（有完全行為能力）| 民法一般同意規定 | 步驟 1（子女）+ 步驟 2（長者語音）即完整 |
| MCI 確診長者（意思能力受限）| 民法 §14-15 輔助宣告 / 監護宣告 | 步驟 3（第三方見證）必加；律師評估是否需法院宣告輔助 🟡 |
| 法定監護人代理同意 | 民法監護人 §1098-1101 | 監護人可代行步驟 2 長者同意；但長者本人有拒絕的最終保留權 |
| 安養信託情境 | 信託法 + 老人福利法 | 信託財產不得由 AI 直接操作（N8 紅線：禁代理簽署）|
