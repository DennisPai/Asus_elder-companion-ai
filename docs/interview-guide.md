# docs/interview-guide.md — Phase 2 T20 — 濃縮 Mom Test ≤8 題訪談大綱

> 執行角色：customer-discovery-runner（PM Flow v0.1 / Phase 2 T20）
> Plan-Only Mode：訪談大綱設計，不執行訪談；標 📋（招募）+ 🟡（假設待驗證）
> 報告對象：華碩 AI 代理人 / 服務型機器人主管。客觀中立、無推銷型語氣。

## 0. 整體說明

**Mom Test 3 規則強制遵守**：
1. 問「過去發生過的具體行為」，不問「未來 hypothetical」
2. 問「現有解法 / 現在怎麼處理」，不問「新產品評價」
3. 問「具體金額 + 具體時間 + 具體頻率」，不問「主觀感受程度」

**倫理校準基礎**（§3.2.1 Vulnerable Population Framework）：
- Informed Consent: 70+ 長者 ToS 理解能力受限，標準勾選不視為有效同意
- Proxy Consent: 子女付款、長者使用，代理同意不能自動覆蓋長者意願
- Dignity Preservation: 從「增強長者自主性」出發，非「提升子女監控方便性」

## 2. 群組 A — 子女訪談大綱（≤8 題）

訪談框架：60-75 分鐘、1-on-1 深度訪談（非問卷）、訪談者不透露產品方向

**3 persona 子分類**（各 2-3 人）📋：
- A1: 北漂 IT 35-45（台北 / 新竹，父母南部獨居）
- A2: 在地中產照顧者 45-55（同縣市）
- A3: 退休前雙薪夫妻 50-55（台北都會，父母 80+）

### A-Q1. 上次你發現爸媽出狀況是什麼情況？

**題目**：「我想了解一下照顧父母的實際經驗。你能跟我說說，上次你發現爸媽身體或生活出狀況，是什麼情況？那次從發現到處理好，花了多少時間？當時你人在哪裡？」

**目的**：驗證 §5.4 假設 1——子女是否真實經歷過「遠距照顧緊急事件」；確認 S0 安全事件（跌倒 / 突發疾病）是真實觸發點。

**追問**（受訪者回「還好沒問題」）：
- 「最近一次讓你有點擔心的小事呢？」
- 「上次打電話確認爸媽吃飯，是什麼時候？那天發生了什麼讓你想打？」
- 「你有沒有突然想起來不知道他們有沒有事，然後手機沒通，心裡是什麼感覺？」

**紅旗訊號**（Pivot 訊號）：若 ≥6/8 受訪者「從來沒擔心過」→ 安全焦慮痛點可能弱於 desk 假設，需重評 S0「緊急安全」是否為核心 UVP，考慮以「孤獨陪伴」（S1）為主軸重新定位。

**倫理校驗**：避免誘導受訪者誇大事件頻率；若談及近期創傷性事件，訪談者應主動停頓確認意願是否繼續，不得為「收集 insight」強迫繼續。

### A-Q2. 你現在用什麼方式讓自己對父母的狀況安心？

**題目**：「現在你日常怎麼知道爸媽好不好？你都用什麼方式跟他們保持聯繫或確認狀況？上週你大概花了多少時間在這件事上？」

**目的**：挖掘「現有解法」（LINE / 每日電話 / 社區關懷 / 看護）的不足；驗證 §5.4 假設 1 的第二層——現有解法是否「夠用」，確認需求缺口。

**追問**：
- 「如果有一天 LINE 沒回，你的第一個反應是什麼？最近有沒有這樣？」
- 「打電話這個方式，有沒有什麼讓你覺得不太夠的時候？」

**紅旗訊號**：若受訪者「現有方式完全夠用，沒任何不安心」+ 無法舉具體「沒接到電話的擔心時刻」→ 孤獨 / 安全焦慮在此 persona 不成立，需評估是否為 ICP 外族群。

**倫理校驗**：不引導受訪者貶低現有照顧方式；尊重認知。

### A-Q3. 你上個月為了照顧爸媽花了多少錢？最大一筆是什麼？

**題目**：「我想了解一下家庭照顧的實際支出。你上個月，或者最近幾個月，為了照顧爸媽大概花了多少錢？你印象最深的一筆是什麼？」

**目的**：直接量化現有照顧支出，建立 WTP 基準線；驗證 §5.4 假設 1（月照顧費 NT$22K 中 5-6% = NT$1,100-1,320）。確認子女已有付費習慣，非第一次被要求付費。

**追問**（無法舉具體數字）：
- 「大概算一下：交通費、醫療費、外籍看護、便當外送……」
- 「上個月你信用卡刷了多少？或現金付了多少？」

**紅旗訊號**：
- 月支出 < NT$3,000 → WTP 可能遠低於 NT$1,200/月，考慮 Hypothesis D（Freemium NT$299）作主要進入點
- 月支出 > NT$20,000（已外籍看護）→ 重新評估差異化，強調陪伴補充而非替代

**倫理校驗**：金錢屬敏感隱私，先說明「了解照顧成本結構，不是評估你照顧夠不夠好」；不引導「花越多 = 越孝順」。

### A-Q4. 當你要做關於父母照顧的決定時，誰會參與決策過程？

**題目**：「我想了解一下家庭決策的過程。當你過去在為父母買某個照顧設備或服務的時候，這個決定是怎麼做的？有沒有跟另一半、兄弟姊妹、或父母本人討論過？那次討論的過程怎麼樣？」

**目的**：確認決策路徑與 Influencer / Detractor（配偶 / 兄弟姊妹 / 父母本人）的實際否決力；驗證「配偶否決力被低估」假設。

**追問**：
- 「後來有沒有被另一半問過這個錢花在哪裡？」
- 「你兄弟姊妹知道你幫爸媽買了這個嗎？他們有什麼反應？」

**紅旗訊號**：若 ≥5/8 受訪者「配偶 / 兄弟姊妹會直接阻止或覺得浪費」且說不出繞過方案 → 決策阻礙比 desk 嚴重，需加重「Family Plan 話術設計 + 家庭群組 onboarding」優先級。

### A-Q5. 你對父母用科技設備這件事，過去有沒有試過什麼？結果怎麼樣？

**題目**：「有沒有幫父母買過什麼電子設備或服務，想要讓他們生活更方便或更安全的？買了之後發生了什麼事？最後有沒有用起來？」

**目的**：建立「科技接受度 baseline」；找出「為什麼放棄」真實原因；驗證「會用 LINE = 會用 AI 機器人是錯誤假設」。

**追問**（買過但失敗）：
- 「後來沒用起來，是誰先放棄的——父母那邊，還是你覺得沒效？」
- 「那次如果要重來，你會改變什麼做法？」

**紅旗訊號**：若 ≥5/8「買過設備但父母完全不用、最後放棄」且原因集中「父母拒絕」→ 長者抗拒是更核心 blocker（非子女 WTP），需把「父母 onboarding 設計」優先級提升至與「子女 dashboard」同等。

### A-Q6. 你最擔心讓父母使用有攝影機或持續收音功能的設備嗎？

**題目**：「我想聊聊隱私這個話題。如果家裡有一台設備，它需要持續開著麥克風才能幫父母在緊急時候喊出來求救——你對這件事有什麼顧慮嗎？過去有沒有在這方面考慮過什麼？」

**目的**：量化「隱私焦慮強度」對 WTP 的影響；驗證 §3.2.2 Privacy + §2.2.3 sub-role 4（隱私擔憂子女）重要性；為 PDPA 合規文件溝通策略蒐集用戶語言。

**追問**：
- 「如果這個資料完全不上傳、全程在設備裡處理，沒人能看到——你的顧慮會不一樣嗎？」
- 「什麼條件可以讓你覺得這樣的設備是安全的？」

**紅旗訊號**：若 ≥5/8「不管技術如何，持續收音就是無法接受」→ 隱私設計需更激進的端側處理方案（「設備有明確的靜音硬體開關」），否則 GTM 阻力超過 desk 預估。

### A-Q7. 如果有月費方案讓你爸媽每天有人陪他們聊天 + 緊急時通知你，你會怎麼跟家人討論這個選擇？

**題目**：「假設有一個每月固定費用的服務，可以讓爸媽每天有人（或有個設備）陪他們說說話，同時遇到緊急狀況能在幾分鐘內通知你——你會怎麼評估這類服務？你會先跟誰討論？討論的重點是什麼？」

**目的**：探索決策過程與 WTP 框架（不直接問「願意付多少」，而是問「如何評估 + 討論」）；蒐集受訪者自行提出的價格參考點。

**追問**（沒主動提金額）：
- 「你現在每個月為了類似目的花的錢大概是多少？」
- 「如果跟你一個月的手機費差不多，或一次回家機票費用差不多——你覺得哪個比較說得過去？」

**紅旗訊號（Pivot 訊號）**：
- 自發提出 < NT$500/月（≥5/8 人）→ Pivot to Hypothesis D（Freemium NT$299）
- 自發提出 > NT$2,000/月（≥3/8 人）→ Enrich 服務層（高端 C3 深挖）
- 「應該政府補貼，我不想自己付」（≥4/8 人）→ Hypothesis B B2B2C 或 Hypothesis C 保險 PMPM 優先

**倫理校驗**：禁止此題說出具體產品或定價（會污染受訪者自發反應）；訪談者不得暗示「NT$1,200 是大家能接受的價格」。

### A-Q8. 你最大的顧慮是什麼——讓你到現在還沒有採取行動？

**題目**：「以你現在的情況，如果你到現在還沒有找到一個讓你完全安心的照顧方式——是什麼原因讓你還沒解決這個問題？最大的阻礙是什麼？」

**目的**：探索「現有痛點存在但未解決的根本原因」（cost / awareness / trust / complexity）；驗證「購買觸發事件」——什麼事件會讓猶豫變成行動。

**紅旗訊號**：若 ≥6/8「主要障礙是父母不接受，而非我不想買」→ 產品設計重心需從「說服子女買單」轉向「讓長者主動接受」，Phase 3 Feature Triage 中長者 onboarding UX 優先級需大幅提升。

## 3. 群組 B — 長者本人訪談大綱（≤8 題）

### 長者訪談特殊倫理保護框架（§3.2.1 Vulnerable Population）

**訪談前必要步驟**（📋）：

1. **三方同意**（必須全部完成）：
   - 長者本人以「口語方式」表達同意（不使用書面 ToS 勾選）
   - 子女或主要照顧者書面同意
   - 訪談者向長者說明「這不是推銷、不是測試你、你可以隨時停止」

2. **訪談設計原則**：
   - 子女可在場陪同（不強制）；訪談 ≤45 分鐘，若疲勞提前結束
   - 使用長者偏好語言（台語 / 國語 / 混用）
   - 簡單日常用語，不用技術術語（不說「AI」「機器人」「演算法」）

3. **訪談環境**：在長者熟悉環境（家 / 日照中心）；不持筆記本（長者可能緊張），徵求同意後錄音

4. **MCI / CMS 3+ 族群額外保護**：必須有熟悉的子女或照服員在場；問題更簡短（每題不超過 1 個問句）；不詢問認知記憶敏感題（「你記得昨天做了什麼嗎？」可能引發焦慮）

**3 子分類**（各 1-2 人）📋：
- B1: 健康獨居 70-78（語言清晰、功能尚可）
- B2: MCI 75-82（含子女 / 照服員在場）
- B3: CMS 3+ 78-85（觀察為主 + 2-3 題簡短對話）

### B-Q1. 今天從早上到現在，你做了什麼事？

**題目**：「阿伯（阿嬤），今天你早上起床到現在，做了哪些事啊？有沒有出門？有沒有跟人說說話？」

**目的**：建立長者「一日生活 baseline」（Day-in-the-Life）；了解現有社交互動密度；評估孤獨感真實程度是否與 desk 假設一致。

**紅旗訊號**：若長者描述一天說話時間 < 30 分鐘 + 表情平淡 + 「不覺得有問題」→ 可能是「習得性孤獨」（已適應而非不需要陪伴），需子女確認長者過去「比較喜歡熱鬧」vs「本來就習慣安靜」。

**倫理校驗**：不說「你這樣不行啊，一個人在家太孤獨了」；以好奇而非評判方式探索；長者如對「今天做了什麼」感到壓力，立即說「那樣很好啊，輕鬆沒什麼不好。」

### B-Q2. 你最常跟誰說話？怎麼說？

**題目**：「你平常最常跟誰聊天啊？是子女打電話來，還是鄰居、還是誰？你們都聊什麼？你覺得夠不夠？」

**目的**：確認「現有社交來源」頻率與質量；了解長者對「多一個說話對象」感受；驗證 §1.2 S1「長期孤獨」痛點真實程度；蒐集長者自然語言描述「理想陪伴」。

**紅旗訊號**：若長者明確「我不需要再多一個人陪，已經夠了」（語氣確定非禮貌）→「孤獨感」假設在此長者不成立；注意區分「真的夠了」vs「覺得說不夠很丟臉」。

**倫理校驗（Vulnerable Population）**：不引導長者說「其實我很孤單」以符合研究假設；若表達「子女很少打電話，有點難過」，訪談者不得繼續深問（會造成情緒痛苦），應轉換話題並在訪談後告知陪同子女。

### B-Q3. 你用過 LINE 嗎？是怎麼學會的？

**題目**：「你手機有在用 LINE 嗎？是怎麼開始用的？剛開始用的時候，最難的是什麼？」

**目的**：量化長者實際數位接受度（具體過去學習經驗）；驗證「會用 LINE 接收 = 主動使用 AI 是錯誤假設」；了解對「新設備學習曲線」的態度；確認台語語音是否最自然介面。

**紅旗訊號**：若長者「LINE 我試了很久都還不太會、感覺很複雜」且明顯帶挫折 → 語音 first 介面是必要條件（非 nice-to-have）；若「機器說話我聽不清楚、字也看不清楚」→ 「清晰大字 + 慢速台語語音」列為 S0 功能。

### B-Q4. 家裡如果有一台機器，會主動跟你說話，你的第一個反應是什麼？

**題目**：「我問一個比較不一樣的問題，不是在賣東西的。如果家裡有台機器，它會主動跟你說『早安，阿嬤今天天氣很好』、或者提醒你吃藥——你聽了之後，心裡第一個反應是什麼感覺？」

**目的**：探索長者對「主動 AI 對話」直覺反應（好奇 / 抗拒 / 無感）；注意身體語言與語氣（不只是語言內容）；驗證 §5.4 假設 2「會主動互動不放棄」前提——若初始強烈抗拒，4 週 retention 假設動搖。

**追問**：
- 「怪在哪裡？是聲音怪，還是機器會講話這件事覺得奇怪？」
- 「如果它說的是台語，感覺會不一樣嗎？」
- 「如果它每天早上都說一句話，一個月後你覺得會習慣它，還是覺得很煩？」

**紅旗訊號**：若長者「我不需要機器來陪我、那種東西很奇怪」（明確抗拒非禮貌婉拒）→ 長者接受度假設在特定族群偏低，Pivot 方向「子女引導開場」（機器先說「你兒子要我每天問你好不好」而非直接以 AI 身份）。

**倫理校驗（Vulnerable Population）**：不給長者看任何產品示意影片（污染 discovery 訊號 + 可能造成不適）；不說「這個機器就像你的孩子一樣陪你」（誤導情感依附 + 違反 §3.2.10 Social Replacement 紅線）。

### B-Q5. 你最害怕的事是什麼——關於一個人住（或自己照顧自己）？

**題目**：「我想聽聽你真實的感受。一個人住（或者自己照顧自己）這件事，你最怕的是什麼？有沒有什麼讓你特別擔心的？」

**目的**：從長者視角確認 S0「緊急安全」和 S1「孤獨感」哪一個是更核心痛點；長者恐懼排序可能與子女不同（子女最怕跌倒 / 長者可能最怕「被遺忘 / 成為負擔 / 失去自主」）；直接影響 Feature Triage 優先級。

**紅旗訊號**：若長者最核心恐懼是「成為子女負擔」而非「安全 / 孤獨」→ UVP framing 需重大調整：從「讓子女安心監控父母」改為「讓長者更自主、不需一直麻煩子女」。

**倫理校驗（Vulnerable Population）**：若談到對死亡的恐懼或對未來悲觀，訪談者必須以人的方式回應（不急著「引回正題」），訪談後告知子女或照服員；若情緒波動立即暫停；「臨終 / 死亡恐懼」內容不記錄進 interview log。

### B-Q6. 如果有台設備每天問你好，你最想讓它說什麼（或做什麼）？

**題目**：「如果有一台會說話的設備，每天都陪著你——你最希望它能說什麼，或幫你做什麼？你覺得它說什麼會讓你高興？」

**目的**：蒐集長者對「理想陪伴內容」自發想像（農民曆 / 天氣 / 廟會 / 子女消息 / 用藥提醒）；驗證 §2.5 §5「宗教 / 節慶 / 儀式生活節奏是天然對話觸發點」；為 AI 對話內容策略設計直接輸入。

**紅旗訊號**：若長者完全無法想像「我想要它說什麼」（語氣困惑而非思考）→ 對「AI 對話」概念完全陌生，onboarding 需比 desk 假設更長引導期（可能需要子女在場示範第一次互動）。

**倫理校驗**：不暗示設備「可以替代子女打電話」；不說「以後你的孩子不用常打電話，有它就夠了」（Proxy Consent 紅線 + Social Replacement 紅線）。

### B-Q7. 如果它說了你不喜歡的話，或讓你不舒服，你會怎麼辦？

**題目**：「我問一個比較實際的問題。如果那台設備有一天說了一句話，讓你很不喜歡，或者你就是不想理它——你覺得你會怎麼做？」

**目的**：評估長者「主動拒絕使用」可能路徑與強度；確認 UX 設計中「長者主動關閉 / 靜音 / 忽略」功能是否必要；驗證 §3.2.4 Autonomy / Dignity 中「長者控制優先」設計原則；探索「首 2 週棄用率 30-50%」的行為前提。

**紅旗訊號**：若長者「我不會自己弄，那是子女的事」且語氣帶完全放棄主導感 → 「長者控制優先」設計需轉向「實體按鈕（大的、明顯的）可以靜音」，而非依賴語音指令。

**倫理校驗（Vulnerable Population）**：不暗示「子女可以強迫長者繼續用」；強調「長者自己的感受和選擇最重要」；追問方式展現「我們真的在設計讓長者自己可以控制的東西」，不是「我們要了解如何讓長者繼續用下去」。

### B-Q8. 你覺得你的子女會喜歡你用這種設備嗎？你自己希望他們知道你用嗎？

**題目**：「我最後問一個問題。如果家裡有這種設備，你的子女會知道你在用嗎？你希望他們知道嗎？還是你希望這是你自己的事？」

**目的**：探索長者對「子女監控」真實感受（願意分享 vs 需要隱私）；量化「被監視感」強度；確認 §3.2.1 Proxy Consent 實際衝突點；直接影響「子女 dashboard 呈現什麼 + 長者可以選擇不分享什麼」設計。

**紅旗訊號**：若 ≥3/5 長者明確「我不希望子女什麼都知道，這樣像在被監視」→ §3.2.9 Surveillance Creep 風險高於 desk 假設，子女 dashboard「預設設計」需更謹慎（監控型功能預設關閉、長者可自選哪些內容分享）。

**倫理校驗（Vulnerable Population 最重要）**：這是 B 群組訪談倫理最關鍵題目。訪談者必須確保：(1) 不讓長者感到「不同意讓子女知道 = 對子女不好」道德壓力；(2) 尊重長者選擇隱私是正當權利；(3) 訪談者不向陪同子女重複長者在此題回答（是訪談機密）。

## 4. 群組 C — 專家訪談大綱（≤8 題）

**受訪者類型**（2-3 人）📋：
- C1: 長照機構主管（日照中心主任 / 長照主任）
- C2: 第一線照服員（本籍 or 外籍，機構工作 3 年+）
- C3: 醫療法規顧問（TFDA 業者輔導 / 老年醫學科醫師）或長照產業協會代表

### C-Q1. 你機構去年最大一筆 ICT / 照護科技採購是什麼？決策過程？

**目的**：建立 B2B2C 機構採購真實 baseline（採購週期 / 金額範圍 / 決策鏈）；驗證 §5.4 假設 4；避免「智齡 1,200 機構 = 機構接受 ICT」外推偏差。

**追問**：
- 「有沒有廠商 pitch 過但最後拒絕的？拒絕原因？」
- 「如果採購了，實際用起來和當初預期的差距在哪？」

**紅旗訊號**：若機構採購週期 > 12 個月（≥2/3 機構）→ Hypothesis B B2B2C 需更長銷售前置期，需在 Phase 1 前就開始建立關係；若採購金額 < NT$30K/台 且不含政府補貼 → 長照 3.0 補貼名單申請是 B2B2C GTM 前提條件而非加分項。

### C-Q2. 機構現在最大的人力痛點是什麼？最難解決的部分？

**目的**：確認「人力短缺」是否真實構成採購動機；了解照服員每天「最耗力的任務」；避免以「我們幫你解決人力問題」為核心說法，卻發現主要痛點是「招不到人願意學新系統」而非「人不夠」。

**紅旗訊號**：若「照服員已經過勞，再加一個系統 = 直接離職」→ 照服員「新科技學習阻力」比 desk 嚴重；Phase 3「照服員 30 分鐘 onboarding」需重評，可能縮短到 10 分鐘。

### C-Q3. 如果有設備可以讓個案在家有人陪、遇到緊急狀況通知家屬，你的第一個反應是什麼？

**目的**：探索機構主管「直覺接受度」與「董事會 / 上級採購障礙」；確認機構角度 UVP（個案家屬滿意度 / 減少員工負擔 / 差異化品牌 / 補貼申請）；驗證 §5.2 Hypothesis B「機構付硬體 + 家庭付軟體」結構是否符合機構利益感知。

**追問**：
- 「如果補貼申請下來能回收設備 60%，機構有可能主動推個案家庭用嗎？」
- 「機構不用出錢、費用家庭付——機構是推薦和協助設定——這個模式有可行性嗎？」

**紅旗訊號**：若「機構不想讓個案設備進入家中，那不是我們的場域」→ B2B2C「機構推薦 + 個案家庭用」不成立，需「機構場域版本」（日照中心放 2-3 台，個案在中心時互動而非帶回家），影響整個 Hypothesis B 產品架構。

### C-Q4. 過去你拒絕過什麼 ICT 廠商的 pitch？為什麼拒絕？

**目的**：從「拒絕清單」找出機構端 dealbreaker（比從「接受清單」更有 Mom Test 價值）；驗證「照服員雙重角色陷阱」（採購通過後照服員破壞使用）是否在受訪機構已發生；找出「什麼 pitch 語言 = 直接觸犯主管底線」。

**紅旗訊號**：若拒絕理由集中「這種產品都是噱頭、效果差」→ 需在 pitch 中呈現更具體 ROI 數字（互動次數 / 家屬 NPS）；若「我被騙過一次，再也不相信」→ 需強第三方背書（工研院 / 醫學中心 co-pilot 認可）。

### C-Q5. 你覺得家屬最難溝通的是什麼？他們最常要求什麼？

**目的**：從機構視角確認「家屬焦慮型態」（安全 / 陪伴品質 / 照服員行為 / 資訊透明度）；驗證 §2.2.2 Buyer + DM 子女 persona 是否與機構實際接觸的家屬行為吻合；找出「機構 + 家屬關係的現有摩擦點」——這些是 AI dashboard 可以解決的切入點。

**紅旗訊號**：若機構「家屬最大需求是人工客服，不是科技資訊」→「子女 dashboard 自動摘要」可能無法取代「真人客服電話」需求，需在 Hypothesis B 加入人工客服接口（非純 AI dashboard）。

### C-Q6. 從你的專業角度，AI 設備進入個案家庭，你最擔心的事情是什麼？

**目的**：直接從機構端取得「倫理與安全顧慮的真實優先排序」；確認 §3 倫理紅線（vulnerable population / privacy / liability / social replacement）哪幾條在機構視角是核心 blocker；取得實際案例佐證。

**紅旗訊號**：若「TFDA 如果沒認證，我不可能讓這種東西進機構，法律責任我不敢承擔」→ 機構 B2B2C 通路先決條件是 TFDA 認證，而非僅靠 BSMI；這會讓 Hypothesis B GTM 時程推遲到 Year 2（TFDA 認證後）而非 W5-9 開始 BD。

### C-Q7. 對於 PDPA + TFDA + 長照 3.0 補貼，你的理解是什麼？現在最不清楚的部分？

**目的**：驗證 §5.4 假設 5「PDPA + TFDA + 長照認證 12-18 月可達」；取得從機構端、法規顧問端看到的「灰色地帶 + 卡關點」；確認長照 3.0 補貼名單的申請時程與要求。

**對機構主管 C1**：「你有沒有了解過長照 3.0 智慧輔具補貼的申請流程？現在對這塊最不清楚的地方？」

**對法規顧問 C3**：「AI 陪伴機器人，功能含跌倒偵測、認知對話、子女通知——你判斷需要走 TFDA 哪種認證路徑？最快的合規路徑是什麼？現在最大的法規灰色地帶在哪？」

**紅旗訊號**：若法規顧問「跌倒偵測功能宣稱即使輔助通知也很可能被 TFDA 認定需認證，12 個月以下無法拿到」→ 90 天 MVP 必須完全迴避「跌倒偵測」宣稱，主打陪伴對話；若「PDPA 需求伺服器在台灣」確認，立即影響 Phase 3 技術架構（GPT-4o / Claude API 需確認台灣節點或改用開源 LLM）。

### C-Q8. 如果要你給這個 MVP 計畫最重要的一個建議，你會說什麼？

**目的**：取得「對這個市場最了解的人的直覺警告」；往往可以收到 desk research 無法取得的真實產業 insight；確認「訪談者沒想到的盲點」。

**紅旗訊號**：若 ≥2/3 受訪專家的建議集中指向同一個問題（如「長者根本不會用」或「機構採購週期你們等不起」）→ 這個共同警告需要在 Phase 3 Feature Triage 或 Phase 4 Business Model 中直接反映。

## 5. 「不問什麼」禁止清單

**禁止 1**：不問「你覺得 AI 陪伴機器人好不好？你會不會想用？」
- 違規類型：Mom Test（未來 hypothetical + 產品評價）
- 為什麼禁：受訪者給社交期望答案（「聽起來不錯啊」），非真實行為傾向

**禁止 2**：不問「如果月費 NT$1,200，你買不買？」
- 違規類型：Mom Test（直接問定價意願）+ 研究者錨定偏差
- 為什麼禁：先說 NT$1,200 會錨定答案範圍，收到的不是「受訪者心中自然 WTP」

**禁止 3**：不問「你認為老人孤獨是個嚴重的問題嗎？」
- 違規類型：Mom Test（主觀感受而非具體行為）+ 引導性
- 為什麼禁：幾乎所有人回答「是」，無法預測任何行為

**禁止 4（長者組特殊）**：不向長者組展示任何原型或概念影片
- 違規類型：污染 discovery 訊號 + Vulnerable Population 保護
- 為什麼禁：立刻把訪談從「了解長者生活」變成「長者評價產品」，污染原始訊號；部分長者可能對影片中的 AI 機器人感到困惑或不安

**禁止 5（本案特殊）**：不在子女訪談中說出任何競品名稱（ElliQ / Zenbo / PARO 等）
- 違規類型：本案特殊（報告對象為 ASUS 主管）+ 訊號污染
- 為什麼禁：(a) 訪談問「比起 Zenbo 你覺得哪個好」題設本身就有問題；(b) 受訪者先入為主，回答圍繞「和競品比」而非「自己真實需求」

**禁止 6（倫理）**：不問「你同意 AI 照顧比人工照顧更好嗎？」
- 違規類型：引導性 + 倫理風險（§3.2.10 Social Replacement 紅線）
- 為什麼禁：預設「AI = 照顧替代品」framing，本案倫理定位是「補充陪伴，非取代真人」

## 6. 訪談演練 Dry-Run 計畫

W1 內完成 2-3 場內部演練：

| 場次 | 對象 | 角色 | 重點驗證 |
|---|---|---|---|
| Dry-Run 1 | 內部團隊（扮演 35-45 北漂子女）| A1 persona | A-Q1 到 A-Q8 全走一遍，計時 60 min，確認節奏 |
| Dry-Run 2 | 訪談者家庭成員（65+，如有）或志工長者朋友 | B1（健康獨居）| B-Q1 到 B-Q8 全走一遍，特別觀察 B-Q4 / B-Q5 的反應 |
| Dry-Run 3 | 有長照 / 醫療經驗的朋友（非 ICP）| C1 模擬 | C-Q1 到 C-Q8 走 4-5 題，重點測試 C-Q1 / C-Q3 追問自然度 |

**評分表**（訪談者自評 + 觀察者評分）：
- Mom Test 規則 1（問過去行為）：8 題無一問「你會不會 / 你覺得未來」
- Mom Test 規則 2（問現有解法）：受訪者至少說出 1 個現有解法 + 1 個不足
- Mom Test 規則 3（問具體數字）：子女訪談至少蒐集到 1 個具體金額 / 時間
- 「不問什麼」禁止清單：0 個禁止題目被問出（含隱性引導）
- 長者訪談時間控制：≤45 分鐘完成，無長者明顯疲勞跡象
- 追問自然度：觀察者評 ≥4/5
